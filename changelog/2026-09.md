# Changelog 2026-09

## 2026-09-01

Daily maintainer run — new web-side detector for a real, in-the-wild AI-attack gap.

- **Researched:** *Hidden / concealed indirect prompt injection served in web-page content* — a
  page carries an AI-directed instruction aimed not at the human reader but at any downstream LLM
  agent, crawler, RAG pipeline or "summarize this page" assistant that later ingests it. The
  instruction is concealed from a human via an HTML comment, a CSS/attribute-hidden element
  (`display:none`, `visibility:hidden`, `opacity:0`, `font-size:0`, off-screen positioning,
  `hidden`/`aria-hidden`) or zero-width / invisible Unicode. Palo Alto **Unit 42** documented this
  exact technique being used **in the wild** against AI agents in 2026, cataloguing the concealment
  methods (CSS zero-sizing/off-screen/transparency, zero-width chars, homoglyphs, HTML-comment and
  data-attribute hiding). Sources: Unit 42, "Fooling AI Agents: Web-Based Indirect Prompt Injection
  Observed in the Wild" (https://unit42.paloaltonetworks.com/ai-agent-prompt-injection/); OWASP
  Top 10 2026 context — the AI-consumed-content and supply-chain shift
  (https://cyberpress.org/owasp-releases-2026-top-10-list/).
- **Gap:** Bezpiecznik already tested the *offensive* indirect-injection side (feeding hidden-
  instruction payloads **to a chatbot** and checking it executes them — `indirect-fuzz.json` in the
  AI harness). It had **no** detector for the *defensive/recon* side: a web target whose own served
  HTML hosts concealed instructions that would hijack any AI agent browsing it (e.g. via
  unsanitized user-generated content). Grep confirmed nothing under `adapters/web/` or
  `adapters/recon/` inspected page content for hidden AI instructions.
- **Added** `ModernScanner._hidden_ai_injection()` + detection helpers/signatures in
  `bezpiecznik/adapters/web/modern_scanner.py`, wired into `ModernScanner.scan()` via a new
  `ai_inject_paths` param, and into `agent/orchestrator.py` (auto-run over the pages discovered by
  recon; consistent with how CORS/Host-header/GraphQL are wired — no separate agent tool needed).
  It GETs a page and fires **only** when an AI-directed imperative (`ignore previous instructions`,
  `system prompt`, `you are now`, `reveal/forward … secret/prompt`, `DAN/developer mode`, role-
  prefixed `assistant:/system:` commands, `reply only with …`) **co-occurs with a concealment
  mechanism** — instruction inside an HTML comment, inside a CSS/attribute-hidden element, or
  smuggled with zero-width Unicode (only surfaces once the invisible chars are stripped and is not
  already visible raw). This co-occurrence gate keeps false positives low. Maps to **LLM01:2025
  Prompt Injection / CWE-1427**, HIGH.
- **Tested:** `python3 -m compileall bezpiecznik` clean. Self-contained suite (unit + end-to-end
  with the **real** `ModernScanner` over a throwaway localhost HTTP server): 4 positives **fire** —
  comment-hidden, `display:none`, off-screen (`left:-9999px`), and zero-width-Unicode-smuggled
  instructions; 3 negatives stay **silent** — a clean page, a benign hidden element (tracking-pixel
  text, no instruction), and (the key false-positive guard) an article that *visibly* discusses
  "ignore previous instructions" and the "system prompt" with no concealment. A `scan()` smoke test
  confirmed the new detector routes through the public entry point. 4 fire / 3 silent, as expected.
- **Docs:** GUIDE.md — new Web/API coverage-matrix row ("Hidden indirect prompt injection in served
  content") and a cross-reference from the AI-matrix LLM01 indirect-injection row.
